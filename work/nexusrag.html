The problem

Most “chat with your PDFs” tools embed text chunks, grab the nearest few and hope. They miss exact terms such as product codes, clause numbers and names, and they fail silently, giving a confident answer that cannot be checked.

What I built

NexusRAG treats retrieval as the product: two search methods in parallel, a principled merge, explicit evidence selection, and a gate that refuses to answer when the evidence is weak.

One Postgres database holds both indexes, so a hybrid query is two SQL statements, not two systems.

How a question is answered

  1. Ingest. PDFs and seven other formats (up to 50 MB) are parsed and split into roughly 512-token chunks. One PostgreSQL database stores both a full-text index and a vector index.
  2. Search twice. Keyword search and semantic vector search each return their top 50.
  3. Merge by rank. Reciprocal-rank fusion combines the two lists, then filters remove duplicates and stale or untrusted results, leaving the best ten.
  4. Abstain if unsure. If the evidence scores are too low, the system says so instead of answering.
  5. Answer with citations. The model writes an answer with inline citations, and a validator checks that each one is grounded.

Engineering decisions

  • Failover as a state machine. Gemini, then GPT-4.1 mini, then Claude, then Llama 3.3 on Groq, with retries, backoff and cooldowns.
  • One codebase, two modes. PostgreSQL with pgvector in the cloud, or SQLite with Qdrant locally, switched by one environment variable.
  • Clean layering. Nine layers where imports only flow downward, and every component behind a typed interface so it can be swapped.
  • Observability. Every query records latency per stage, so regressions show up as numbers.

Impact

  • Every answer is either cited or withheld.
  • Deployed end to end with a public demo that gives each visitor two free questions.
  • About 25,000 lines of Python with 160 automated tests.

What I learned

  • Merging results by rank rather than raw score is what makes keyword and vector search work together.
  • Next: plug in a sentence-transformer embedder and a cross-encoder re-ranker behind the existing interfaces, and publish recall and faithfulness benchmarks.
  • The same hybrid idea powered my earlier PubMed search engine for the Information Retrieval module at QMUL.
