01The problem

AI coding assistants usually send your code to a large cloud model and hope it guesses correctly. When the model can’t see how your project fits together, it invents file paths and APIs — and you get a confident answer with no evidence behind it.

  • Context gap: generic assistants miss project structure, entry points, dependencies and prior decisions.
  • Trust gap: answers rarely point to real files and line numbers, and nothing checks them before you see them.
  • Privacy and cost: the code leaves the machine, and every token is billed.
My constraintsIt had to run on an ordinary 8 GB laptop, work offline, and cost nothing to use.

02What I built

The idea is simple: let deterministic agents gather the evidence, and let a small local model only explain what they found. Every answer is critiqued and scored before it is shown.

The answer path (centre) and build path (right) share one 4-bit model. Dashed teal lines are model calls; the orange loop is self-correction.

How an answer is produced

  1. Route. An intent router decides whether you’re asking a question, requesting a change or running a command. Anything that writes to disk waits for your approval.
  2. Gather evidence. The orchestrator posts the task to a shared blackboard; agents bid for sub-tasks based on capability, load and track record, then map the repo, read files, trace architecture and run tests.
  3. Critique first. Before any text is generated, a critic agent lists what a correct answer must include.
  4. Reason in parallel. Two or three reasoning chains run with different evidence strategies; a confidence scorer picks the best one.
  5. Check, then retry. The winner is re-scored on relevance, completeness and specificity. Below 0.55 it is regenerated with the critic’s feedback.
  6. Remember. The answer is cached and useful fix patterns are stored, so the next similar question is faster.

Key engineering decisions

  • Speed through caching, not hardware: an answer cache keyed by prompt + repository state (with fuzzy matching), a byte-identical system prefix so parallel calls reuse the model’s KV cache, and speculative decoding. Most prompts went from ~40 s to ~5 s.
  • Fits the machine it runs on: context length and parallel slots adapt to free RAM at launch (32K × 3 down to 8K × 1), with an 8-bit KV cache.
  • Safe tool use: tool calls are forced through a grammar so a small model can’t emit broken JSON, and the loop stops if the same error repeats or after 15 iterations.
  • Code that is tested before you see it: a five-agent council (Architect, CodeGen, Tester, Reviewer, Optimizer) must reach a consensus score of 0.7, then a generate → run → fix loop feeds real errors back to the model.
  • Useful with no model at all: 56 symbolic rules across Python, JS/TS and Go, dependency graphs for 6+ languages and pattern-based security checks.
  • Extensible agents: 17 core agents and 5 council agents in Python, plus 85 specialists defined in Markdown/YAML — new agents without touching the engine.

04Impact

  • Live on the VS Code Marketplace since March 2026: 767 downloads, 30+ active users and 106 releases.
  • Typical response time cut from ~40 seconds to ~5 seconds on CPU.
  • Works fully offline — your code never leaves your machine unless you choose a cloud model.
  • Grew beyond coding into a local “Life OS”: morning briefings across calendar, e-mail and GitHub, cross-repo search, a DevOps dashboard and a secret scanner.

05What I learned

  • A small model is reliable when it only has to explain evidence it was given and is graded before it speaks — the intelligence lives in the system, not the weights.
  • Latency is mostly a caching problem. Avoid generating what you’ve already generated.
  • Next: publish benchmark results for the self-correction loop, and make the newer “brain-and-hands” planner the default once it beats the current path.
