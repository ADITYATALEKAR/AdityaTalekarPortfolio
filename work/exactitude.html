01 — OverviewAutomation the client could trust.

Exactitude publishes tens of thousands of market-research reports. Content, prospecting and data checks were manual, AI-written statistics were drifting from reality, and the website was being hammered by scrapers on a small server. I delivered a revamped website and an autonomous system of seven coordinated agents — with a human approval step before anything goes public.

02 — The briefFour problems, one small budget.

01

Content didn't scale

Blog posts, press releases, LinkedIn updates and outreach emails were written by hand, one report at a time.

02

Prospecting was manual

Finding the right companies for each report took around 10 hours per cycle.

03

Numbers couldn't be trusted

Generated summaries contained hallucinated statistics, and some reports' charts disagreed with their own market-size figures.

04

No budget for AI

The firm couldn't justify a five-figure annual LLM bill — and the production server was a small box under active bot attack.

03 — ArchitectureAgents draft. Pipelines verify. People approve.

Agents only ever create drafts. A dedicated database user can write to the draft tables and the blog/press tables — nothing else — so a misbehaving agent can't touch payments or accounts.

Each agent is a LangGraph node with its own tools and prompt; the graph handles retries, branching and hand-offs. Drafts carry their source report ID and metadata, so a reviewer always sees why something was written before clicking approve. Rejecting a draft deletes it; approving one publishes it into the site's existing blog and press-release tables, so the CMS didn't need to change.

04 — The $0 LLM layerTen providers, thirty-three keys, one interface.

Commercial API pricing for this volume of drafting, enrichment and verification was estimated at $24,000–36,000 a year. Instead, I built a gateway that load-balances across ten free-tier providers — including Gemini, Groq, NVIDIA NIM and Mistral — and rotates 33 API keys.

  • Failover, not fallback. When a provider rate-limits or errors, the call moves to the next healthy provider transparently; agents never see the difference.
  • Key rotation. Keys are spread across providers and cycled so no single key hits its quota.
  • Free compute. Everything runs on GitHub Actions: jobs are split into 8, 12, 20 or 40-way matrices, each shard has a time budget and writes atomic checkpoints, and a crashed shard resumes exactly where it stopped.

05 — Data qualityCitation-grounded, or it doesn't ship.

The most valuable fix wasn't generation — it was verification. I built a pipeline in Python and MySQL that forces every market-size statistic to be grounded in a citable source:

  1. Harvest published market-size and CAGR sentences from 23 research firms' public pages.
  2. For each report, compare its stated figure and its chart data against the published range.
  3. Flag reports whose numbers fall outside the range, or whose charts contradict their own text.
  4. Regenerate with the citations in the prompt, then re-verify before the report is updated.

06 — Company index1.43 million companies on a free runner.

To match reports to the companies that actually operate in each market — the basis for prospecting and outreach — I built an open company index from Wikidata (CC0) and openFDA, enriched with GLEIF LEI records, and embedded with bge-small-en-v1.5.

1.43Mcompany profiles embedded
4,105company websites verified live
1,382wrong links caught and rejected

Matching

For each report the matcher pools candidates from four lanes — current companies, semantic neighbours of “makers and suppliers of <market>”, product-phrase hits and FDA ingredient/device registrations — and keeps the top 70 by trust tier. A web-search lane only adds a company if it resolves to a real entry in the index.

“A wrong link is worse than no link”

Naive matching linked Roche to a small French domain, Johnson & Johnson to its Italian subsidiary and Kellogg to a city website. The fix: drop entities that have a parent organisation, rank by Wikipedia sitelinks, require the host to plausibly match the company name, accept country domains only on exact matches, and verify every URL live. Rejection is the default.

Fitting in 7 GB

The first version ran out of memory on GitHub's 7 GB runners. The rewrite keeps only byte offsets in memory, reads profiles from disk on demand and searches embeddings block by block — 1.4M profiles, no paid infrastructure.

07 — Bot defenceKeeping a 2-core server alive.

The site was being scraped hard by AI crawlers and probed by automated scanners. I wrote custom Cloudflare WAF rules, rate limits and timeouts tuned to the site's real traffic patterns.

17.6Mrequests in 48 hours
1.35Mthreat-flagged and blocked (8%)
~28Kmalicious requests stopped per hour, on average

The rebuilt PHP site deploys through GitHub Actions — rsync over SSH, a syntax check, then a web-server reload — with all secrets moved out of the codebase into environment files.

08 — What I learnedThe unglamorous parts are the product.

  • Verification beats generation. The client cared less about how much the agents wrote than whether a single number was wrong.
  • Least privilege makes autonomy acceptable. A database user that physically can't touch payments did more for the client's trust than any prompt.
  • Free tiers are infrastructure if you engineer for failure. Checkpoints, failover and budgets turned rate limits from outages into non-events.
