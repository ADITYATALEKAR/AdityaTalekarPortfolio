01 — OverviewContinuous, evidence-backed visibility — from the outside in.

Banks run thousands of internet-facing endpoints — websites, APIs, mail servers, CDN edges, cloud buckets, legacy portals — and they change every week. Most institutions only discover an expired certificate, a weak cipher or a forgotten subdomain during a breach or a regulator's visit.

Guardian starts from a single seed domain and does what an attacker's reconnaissance would: discovers the full external estate, measures how every endpoint behaves at the protocol level, maps how systems trust each other, and predicts which weaknesses will escalate. It needs no agents and no internal access — only publicly observable metadata — and it never sends payloads or attempts authentication.

02 — The problemInfrastructure evolves faster than security monitoring.

01

Forgotten systems

Subdomains, legacy servers and abandoned endpoints stay exposed long after anyone remembers they exist.

02

Silent cryptographic failure

Expired certificates, weak ciphers and quantum-vulnerable keys sit undetected — and “harvest-now, decrypt-later” means today's traffic is tomorrow's breach.

03

Hidden trust relationships

Shared certificates and dependencies mean one weak system can compromise others that look healthy in isolation.

04

Snapshots, not history

Traditional scanners produce periodic inventories and lose cycle history, so nobody can say what changed, when, or whether risk is rising.

03 — ArchitectureSix layers, each with one job and hard boundaries.

Discovery feeds a stack of analytical layers. Each layer can only depend on the ones below it, and the boundaries are enforced in code: Layer 0 performs no I/O beyond observation, and Layer 3 is forbidden from reading the wall clock, so results are reproducible.

Discovery (left) feeds an analytical stack (right) that only depends downward. Swap PostgreSQL for the filesystem store with one environment variable.

Discovery module inventory

Category A — passive (15)

TLS SANs and recursive SAN chains, certificate-transparency logs, A/AAAA/CNAME/MX/NS/TXT records, SPF includes, reverse DNS, passive DNS, name mutation and ASN/RDAP lookups.

Active surface

Port scanning, TLS on alternate ports, banners, HTTP probes, a bounded crawler, JavaScript and OpenAPI analysis, response signatures and TLS server fingerprints.

Infrastructure & cloud

Neighbouring and shared-IP correlation, netblocks, JARM, CDN edges, S3/Azure/GCP buckets, CloudFront and Kubernetes patterns.

History & confidence

Revived, expired and orphaned assets; favicon hashes and wildcard coverage; volatility; conflict detection, issuer clustering and global confidence recalibration.

What each layer does

  • Observation. Legal, protocol-level measurements of each endpoint — handshake structure, certificate shape, timing jitter and entropy — turned into 24 deterministic fingerprints and 10 “physics” signals such as drift, oscillation and decay.
  • Trust graph. Endpoints, sessions, identities, trust material and evidence, linked by 11 edge types from depends_on to issued_by, with deterministic path enumeration.
  • Weakness detection. Six detectors fused into clusters like instability, negotiation disruption and cross-axis degradation.
  • Prediction & memory. Bounded per-entity learning state (EWMA α = 0.30, absence decay 0.85) emits predictions up to 90 days out.
  • Decision. An 8-phase campaign model — stable, recon, probe, escalation, structural stress, persistent pressure, recovery, transitional — with hysteresis so alerts don't flap.
  • Posture & compliance. TLS, certificate, HSTS, revocation, WAF and post-quantum findings mapped to controls in PCI-DSS v4.0, RBI guidance and NIST IR 8413.

04 — A scan cycleEvery finding is tied to a cycle, a stage and evidence.

  1. Initialise — sync policy, load the per-tenant Layer 0 baseline.
  2. Discover — passive expansion first, then active; each category gets an exploration pass, and only modules that proved productive get the exploitation pass.
  3. Snapshot — build the snapshot and diff against the last one, sealed with a SHA-256 hash.
  4. Temporal update — record presence, TLS, port and certificate changes over time.
  5. Trust-graph replay — apply the graph delta and persist a graph snapshot.
  6. Evaluate — run Layers 2 → 3 → 4 per entity, then policy patterns.
  7. Persist — write artefacts; on failure, salvage whatever stages completed.

The whole cycle runs under a 600-second budget checked at every stage, with a cycle lock and progress heartbeats so a crashed worker can be detected and recovered.

05 — The trust graphDistricts, roads and buildings.

Raw graphs of a bank's estate are unreadable hairballs. I designed the console to render the trust graph as a city: districts for cloud services, CDN/edge, security vendors, email, infrastructure and evidence; buildings for nodes; roads for dependencies. Analysts can switch to a route mode and click two nodes to trace the shortest structural path between them — the blast radius made visible.

A built-in attack simulator injects five scenarios — compromised endpoint, certificate compromise, coordinated entropy spike, structural lateral movement and persistent low-signal exfiltration — re-runs the pipeline in a sandbox, and reports blast radius, ranked attack paths and the top mitigations.

06 — Key decisionsBank-grade means boring, repeatable and auditable.

01

Determinism as a feature

Same input, same output — always. Even retry jitter is derived from a SHA-256 of endpoint + attempt rather than a random number, and determinism tests guard the trust graph. Auditors can replay any finding.

02

Explore, then exploit

Discovery is budgeted like a bandit: 30-second slices per module, then extra time only for modules that found something. Hard caps (250K nodes, 500K edges) keep a cycle bounded on any estate.

03

Observe, never attack

No payloads, no auth attempts. A language guard even rejects findings phrased as “bypass”, “evade” or “exploit”, keeping output defensive and fit for a bank's governance review.

04

A tiny supply chain

The backend is standard-library Python plus three dependencies (gunicorn, psycopg2, optional curl_cffi). Less to audit, less to break — a real selling point for a security buyer.

05

Resilient to the real internet

A rate controller with circuit breaker and exponential backoff, plus a fallback for bot-challenge pages, keeps scans polite and complete.

06

Hardened by default

PBKDF2-SHA256 with a dummy-digest check so login timing can't reveal which users exist, constant-time comparisons and tenant isolation.
