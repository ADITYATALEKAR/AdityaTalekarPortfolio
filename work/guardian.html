The problem

Banks run thousands of internet-facing endpoints, and they change every week. Most institutions discover an expired certificate, a weak cipher or a forgotten subdomain only during a breach or an audit.

  • Forgotten systems stay exposed long after anyone remembers them.
  • Cryptographic weaknesses fail silently, and quantum-vulnerable keys mean today's traffic can be harvested now and decrypted later.
  • Hidden trust relationships let one weak system compromise others that look healthy.
  • Banks are now shipping AI agents, chatbots and LLM endpoints to the public internet with little idea of how exposed they are — new prompt-injection, over-permissioning and data-leak surface that classic scanners miss entirely.
  • Scanners give snapshots rather than evidence, so nobody can prove what was checked or trust a "nothing found".

What I built

From a single seed domain — name the institution, confirm one domain, click scan — Guardian does what an attacker's reconnaissance would do, but deterministically, fully externally, and without payloads, uploads or login attempts. It discovers the estate, fingerprints every endpoint at protocol level, builds a dependency graph, runs 27 security probes (including an AI-agent/LLM security layer), proves which exposures are actually reachable, and writes every finding to a signed, tamper-evident ledger. The whole scan runs serverlessly on GitHub Actions and the encrypted result is pulled back into a React analyst console.

Discovery (left) feeds an analytical stack (right) that only depends downward: every observation is signed into the atom ledger before probes, proofs and the console read it.

What it does

  • Discovery. Passive (CT logs, DNS, SAN chains, ASN) and active (ports, TLS, JARM, HTTP crawl) modules expand one domain into the full estate, with honest in-scope / third-party / unverified host attribution.
  • Signed atom ledger. Every observation becomes a content-addressed "atom" with a cryptographic receipt in an append-only Merkle transparency log — findings are replayable and tamper-evident.
  • Security probes. 27 probes: TLS/cert hygiene, exposed git/buckets/CI, SSO-bypass paths, plus an AI-agent layer — MCP/model-API endpoints, chatbots, prompt-injection and internal-infrastructure leakage.
  • Provable reachability. A Z3 SMT solver proves whether an exposure is actually reachable, so a finding carries a machine-checkable basis, not just a heuristic.
  • Quantum & dependency risk. Harvest-now-decrypt-later (HNDL) scoring and a provider dependency graph showing where one weak vendor cascades.
  • Analyst console. A 24-page React/TypeScript app that leads with the worst finding and proves exactly which checks ran across how many hosts.

Engineering decisions

  • Provable, not just produced. Every scan records which of the 27 checks ran, across how many hosts — so a clean result is demonstrably clean rather than ambiguous — and every finding resolves to a signed ledger receipt.
  • Serverless scanning. The scan runs on GitHub Actions from a public runner repo that holds no engine code; results are end-to-end encrypted (X25519 + AES-GCM) and only the local private key can open them.
  • Budget discipline. Explore-then-exploit module slices with a reserved observation floor, so expansion can never starve the probe phase.
  • Observe, never attack. No payloads and no authentication attempts; findings are written in defensive language for a bank's governance review.
  • Compliance mapping. TLS, certificate, WAF and post-quantum findings mapped to PCI-DSS v4.0, RBI guidance and NIST IR 8413.

Impact

  • A single one-click external scan maps 500+ endpoints and expands one domain into hundreds of related assets in about five minutes — reconnaissance that takes a security team hours to days by hand.
  • Surfaced genuinely non-obvious findings on real institutions: exposed non-production identity/SSO systems and password-login-beside-SSO paths, each traced to concrete evidence and a signed receipt.
  • Runs the entire scan serverlessly on GitHub Actions with encrypted results, so the platform costs effectively nothing per scan to operate.
  • Presented at IDBI Innovate 2026 as a working product.

What I learned

  • For a bank, provable beats clever: a finding tied to a signed receipt and a reachability proof is worth more than a long, unverifiable list.
  • "We found nothing" is only credible if you can show what you checked — so the scan now records which probes ran, across how many hosts.
  • Running the whole scan on GitHub Actions turned a costly engine into one that runs for effectively nothing per scan.
  • Guardian observes only public metadata and is intended for authorised assessment of an organisation's own estate.
